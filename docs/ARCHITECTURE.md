# 架构与算法

## 数据流

FastAPI 本地服务 → 持久化任务调度 → 本地专用模型 → 素材证据 → 有额度的 API 整理 → 独立复核 → 完整成稿分章 → 阅读与离线导出。

- 语音：Qwen3-ASR-1.7B + Qwen3-ForcedAligner-0.6B；Silero VAD 检查覆盖。保持已有识别参数、上下文重叠与时间对齐逻辑。
- 画面：低分辨率变化扫描、候选变化处细化、OpenCV 几何匹配、YOLOX 教师遮挡；原视频高清截图恢复。画面覆盖与来源记录独立保存。
- 精简：图像信息覆盖与 PaddleOCR-VL 页面内容线索共同决定可分组性；动画终态优先，但不同数字、正负号、矩阵维数或互补遮挡不能仅凭相似背景删除。
- 课件筛选：PaddleOCR-VL-1.6 与 PP-DocLayoutV3 提供有界的页面内容线索，精确重复图共享缓存。此阶段不生成笔记公式；新任务不运行 RapidOCR 或独立本地公式提取。旧任务保持原路线和检查点。
- 文字和公式：整理请求携带字幕与高清原页，API 直接读图，并同时返回逐页 keep、duplicate_of、final_state、replaced_by 等字段。正文与筛选元数据分开校验；元数据错误不丢正文、不触发补收费。只隐藏有安全替代关系的画面，全部原始来源保留。KaTeX 检查生成公式的可渲染性，不证明数学正确。
- 笔记：内部小段控制请求大小并提供相邻上下文，全部素材就绪后整理与复核，完整成稿的语义分章仅调整结构，不重写、丢弃或重复来源片段。

## 一致性和恢复

任务、累计费用放 SQLite；生成文件先临时写入再原子替换，Windows 文件占用采用有界重试。ASR 进度用追加 JSONL，避免读者持有句柄时频繁替换。阶段完成标记与源文件身份/哈希共同决定复用，正常识别逻辑不因发布而改变。

每个付费请求先事务预留费用。成功按 usage 核算，超时保留预留并要求先核账。响应以指纹缓存；显式失败重试才增加对应阶段/来源的尝试序号。唯一确认 ID 防止重复点击和网络重放创建多个尝试。失败正文、原始响应和历史账本保留。

有效 JSON 字符串正文可以独立于损坏的附属纠错字段保存，但截断的正文不能猜补。复核采用唯一精确锚点和原子应用；任一修订不能安全定位时，整组不应用并保留原稿。

## 资源和便携边界

三个独立 CPython 运行时分别承载主服务/图像、PyTorch ASR、Paddle 文档模型。启动器仅管理本目录、本版本实例，停止时请求检查点退出。GPU 槽覆盖模型完整生命周期，并在重模型加载前检查可用显存；快速模式没有固定节流休眠。

便携缓存目录由程序初始化，包含 HF、PaddleX、ModelScope 和临时目录。固定文件清单记录下载来源、revision、大小与 SHA-256；全文件校验及统计签名匹配后才标记准备就绪。文件变化将取消就绪状态。

API 仅绑定 127.0.0.1；拒绝非本机 Host 和跨来源写操作。密钥不放源码、导出、工作流摘要或下载清单；Windows 本地加密跨账户失败时允许继续浏览并提示重新填写。

已有 PDF/PPT/PPTX 直接渲染原页并读取可用原生文字；扫描页同样进入图片请求，不伪造视频时间戳。每页图片哈希、提示、模型与来源目录参与 API 缓存指纹；DeepSeek 按每图最高1024输入tokens预留，受每份笔记总预算约束。整段请求超出图片/48MiB限制时停止并提示，不静默丢页或降为纯字幕。其他兼容供应商采用更保守估算，实际价格需用户正确填写。
